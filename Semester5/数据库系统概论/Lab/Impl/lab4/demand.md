## 2. 实验内容与要求

### 2.1 安全性实验
1. **教材案例复现**  
   在 DBMS 上完成教材第四章的示例：  
   - 建立多个用户。  
   - 在权限变更（授予、回收）后尝试登录，观察并记录行为差异。

2. **权限传递与回收实验**  
   设 A、B、C 为用户，`x` 为某项权限（如对某表的 `SELECT` 权限）。针对下列场景编写 SQL 并分析原因：
   1. A → B → C 授权 `x`；回收 B 的 `x` 权限后，判断 C 是否仍保有 `x`，并验证 `CASCADE` 的效果。
   2. A 同时授权 `x` 给 B、C；回收 B 的 `x` 后，判断 C 是否 still 保留；回收 C 的 `x` 时是否需要指定权限来源。
   3. 总结上述现象背后的机制。

3. **TPCH 业务角色设计**  
   基于 TPCH 数据库，完成以下角色与权限分配：
   - `Supplier_Mgr_Role`：可查看/更新供应商信息（`supplier`）、供应关系（`partsupp`、`part`）及地区维度（`nation`、`region`）。
   - `Sales_Mgr_Role`：可查看/更新客户（`customer`），查看/更新/新增订单（`orders`），查看订单明细与地区信息（`lineitem`、`nation`）。
   - `Senior_Analyst_Role`：可查看所有表数据。  
   创建测试用户、赋予对应角色，并验证每个角色的权限是否按预期生效。

### 2.2 触发器实验
> 本部分在 TPCH 数据库上单独完成。金仓数据库不支持 `REFERENCING` 关键字，可直接使用 `OLD` 与 `NEW` 访问修改前后记录。

1. **订单明细更新触发器**  
   在 `lineitem` 表上创建 `UPDATE` 触发器：当 `l_extendedprice` 或 `l_discount` 被修改时，自动同步更新 `orders` 表中的 `o_totalprice`。

2. **订单明细新增触发器**  
   在 `lineitem` 表上创建 `INSERT` 触发器：当新增订单明细时，自动更新对应订单的 `o_totalprice`。假设新增明细对应的订单已存在。
